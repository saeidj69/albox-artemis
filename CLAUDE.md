## Architecture

**Dependency direction:** `app → modules → components/lib/api`

- **`src/app/`** — Thin routing layer only (page, layout, metadata, server actions). Delegates all UI to module pages.
- **`src/modules/<domain>/`** — Domain-scoped feature modules (authentication, brands, categories, checkout, discovery). Each module owns: `pages/`, `atoms/`, `layout/`, `types/`, `utils/`. Page-specific components live under `pages/<page>/components/`, with page logic kept close to the page. Use `pages/<page>/index.tsx` as the page entry; do not add route-entry indirection folders or a global type dump. Domain logic stays inside its module, and cross-module dependencies go through stable module surfaces rather than circular imports.
- **`src/components/`** — Shared composites (higher-level UI built from primitives). Must not import from `src/modules`, contain feature business logic, or fetch feature data. Promote module UI here only after it is reused across at least two module scopes; shared components should remain generic and theme/design-system driven.
- **`src/lib/`** — Shared UI primitives (Radix-based, unstyled). Must not import from `src/modules`, fetch feature data, or assume app-wide feature/layout details. Shared layers must remain consumable by modules.
- **`src/api/`** — **Read-only.** Generated by Orval from `src/api/config/swagger.yaml`. Never manually edit, move generated files during refactors, or add wrapper directories around generated hooks unless explicitly required. Use generated React Query hooks/functions/models directly. Custom behavior goes in `src/api/mutator/index.ts` (Axios instance with interceptors).
- **`src/styles/`** — Design tokens (`tokens.css`), base styles, typography utilities, animations. Layer order: tokens → base → typography → animations → globals.css glue. Keep `globals.css` as an entrypoint/glue file; colocate specialized module styles with their module and do not add page-specific hacks to route files.

## Component System (`src/lib/`)

Components use a **slot-based pattern** with `tailwind-variants`:

- **`variants.ts`** — Define every visual part as a named slot in `tv({ slots: {} })`, with default styles for the base state. Export `XSlots` and, when applicable, `XSkeletonSlots` types. Use boolean variant keys (`true`/`false`), named string variants, `compoundVariants`, and always define `defaultVariants`; keep state overrides in variants rather than duplicating base styles.
- **`types.ts`** — Props extend `ComponentPropsWithRef<'element'>`. `classNames` is typed as `Partial<Record<XSlots, string>>` for per-slot overrides. Polymorphic components use `as?: C extends ElementType` with `OwnProps & { as?: C } & Omit<ComponentPropsWithRef<C>, keyof OwnProps>`.
- **`ComponentName.tsx`** — Main component exported as `ComponentNameComponent`. Every visual element gets a named slot and every rendered element gets a unique `data-slot`: root is `data-slot="component"`, children use kebab-case names. No hardcoded `className` strings — use `slots.slotName({ className: classNames?.slotName })`.
- **`ComponentName.Skeleton.tsx`** — Skeleton loading state exported as `ComponentNameSkeletonComponent`, using the shared Skeleton primitive and honoring the component’s variants, types, slots, and layout footprint.
- **`index.ts`** — Barrel: `export const X = Object.assign(XComponent, { Skeleton: XSkeletonComponent })`.

**React 19:** `ref` is a normal prop — do **not** use `forwardRef`.

## Routing and Module Boundaries

- Route entries should import the module page directly; do not add route-entry intermediates, large feature UI trees, or business-state orchestration in `page.tsx`.
- Use the global root boundaries (`src/app/loading.tsx`, `src/app/error.tsx`, and `src/app/not-found.tsx`) where applicable rather than duplicating app-wide handling in routes.
- Keep page-specific UI and behavior under the owning module’s `pages/<page>/` directory. Shared UI must remain generic and reusable; never create circular imports between modules, shared layers, and routes.
- Any client component that calls `useSearchParams()` must render inside a React `<Suspense fallback={null}>` boundary to preserve static prerendering.

## State Management

- **React Query** (TanStack) — Server state. Orval generates typed hooks (`useProfile`, `useListBrands`, etc.).
- **Jotai** — Client state. `atomWithStorage` for persistence (e.g., login flow tracking). Atoms live in `src/modules/<domain>/atoms/`.

## Auth Pattern

No middleware. Auth checks happen at centralized protected route/page boundaries (`src/app/(protected)/layout.tsx`); route pages must not duplicate redirects or scatter auth logic. On auth error, redirect to `/auth/login`. In this repository the canonical auth module is `src/modules/authentication/`, including `atoms/` for auth state and `utils/` for auth helpers; any generic cursor-rule reference to `src/modules/auth` maps to this path.

## Testing Conventions

- Keep tests near the module or feature they exercise. Critical flows require at least one happy-path and one failure-path test, especially authentication transitions, protected routes, API error paths, login, impersonation, and other critical journeys.
- Do not refactor a critical flow without regression coverage. Prefer local test setup over unrelated global state when the test does not need it.

## Layout Width Constraint (Critical)

**This is a mobile-only app.** Do not introduce responsive breakpoint variants (`sm:`, `md:`, `lg:`, `xl:`, `2xl:`) for ordinary layout or component variants — write mobile styles only. Use responsive utilities only when a verified cross-platform requirement specifically needs them, and preserve the mobile-first width constraint. Page content must never exceed the Header's width. The Header bar uses the **`w-app`** utility (`src/styles/base.css`): `mx-auto w-full max-w-md` (caps at `448px` / `28rem`). The `Layout.Footer` inner wrapper also uses **`w-app`**. The **`.container`** class only adds horizontal padding (`px-4`) and centers — it does **not** set a max width. On new pages inside the protected layout's `.container`, put **`w-app`** on `<main>` (or the primary content column) so the readable column lines up with the Header and Footer. Do **not** invent one-off `max-w-*` on content boxes; use **`w-app`** for consistency.

### RTL horizontal-overflow guard

`src/styles/base.css` sets `html, body { overflow-x: clip; }`. **Do not remove it.** The root layout (`src/app/layout.tsx`) renders decorative "phone frame" overlays using `fixed` + `calc(50% + 14rem)` positioning. On narrow Android viewports (e.g. Samsung A70 at 412px CSS-px) those calcs resolve beyond the viewport edge, and Android Chrome in RTL can then leak horizontal scroll to the whole document — shifting the page right and clipping the start of every label. The `overflow-x: clip` guard neutralizes that (and any similar future regression) without creating a scroll container, so sticky descendants still work.

### Forms that span main + footer button

When a submit button lives in `Layout.Footer` and its form fields live in `<main>`, put the `<form>` around `<main>` only and keep `<Layout.Footer>` as a sibling outside the form. Wire the submit button with the `form="…id…"` attribute. Example: `src/modules/addresses/pages/new/index.tsx`. Do not wrap both `<main>` and `<Layout.Footer>` inside a single `<form>` — the resulting `form > main.w-app` + `form > Layout.Footer` (itself `fixed` with `w-app`) structure, nested inside the protected-layout `.container` (also `w-app`), triggers RTL width-resolution quirks on Android Chrome.

## Key Conventions

- **Folder names:** lower-case, consistent casing, and aligned exactly with the filesystem (never mix `Auth`/`auth` or create case-only duplicates such as `Layout`/`layout`). Route, module, and import naming must remain consistent; never use mixed-case path variants.
- **Imports:** always use the `@/` alias (maps to `src/`), and match the filesystem’s exact casing. The canonical auth import path in this repository is `@/modules/authentication/...`.
- **RTL:** App is configured for Farsi — `<html lang="fa" dir="rtl">`
- **Standalone output:** `next.config.ts` sets `output: 'standalone'`
- **Env vars:** `API_URL`, `VAPID_PUBLIC_KEY` (exposed via `next.config.ts` env)
- **Utility:** `cn()` from `src/lib/utils/cn.ts` (clsx + tailwind-merge)

- **ALWAYS follow SOLID principles in the React context:**
  - **S — Single Responsibility:** Every component, hook, and utility does one thing. If a component renders UI _and_ fetches data _and_ manages complex local state _and_ handles business logic, split it. Container/presentational separation is the default: data-fetching/orchestration components stay thin and delegate rendering to focused presentational components. A file that needs the word "and" to describe what it does is a refactor candidate.
  - **O — Open/Closed:** Components must be extensible without modification. Use `children`, render props, slot props, and `classNames`-per-slot overrides (see Component System above) instead of adding boolean flags like `isProfilePage`/`isCheckoutVariant`. Never branch a shared component on a caller-specific condition — pass behavior/markup in via props.
  - **L — Liskov Substitution:** Variants of a component must remain interchangeable. A `Button.Skeleton`, a disabled `Button`, and a loading `Button` must all honor the same prop contract and layout footprint. Don't ship a "primary" variant that silently drops `onClick`, or a variant that changes the rendered tag in a way that breaks parents (e.g. swapping `<button>` for `<a>` without preserving form/keyboard semantics).
  - **I — Interface Segregation:** Prop interfaces stay narrow and purposeful. Don't pile every conceivable knob onto one mega-prop type "just in case" — split into focused components or use discriminated unions. Hooks return only what's needed; don't expose internal state to all consumers because one consumer needs it.
  - **D — Dependency Inversion:** Components depend on abstractions, not concrete implementations. Prefer passing data and callbacks in via props over reaching for global stores or router objects deep inside leaf primitives. Respect the existing architecture boundary: `src/lib` and `src/components` must not import from `src/modules` (importing generated types/hooks from `src/api` is allowed and already used in shared composites like `Profile`). That boundary _is_ DIP in practice — don't widen it.

- **ALWAYS follow the Single Source of Truth (SSOT) principle:**
  - Each piece of state has exactly one owner. Never mirror server data into Jotai/`useState` — read it from React Query (`src/api` generated hooks) at the point of use. Never mirror URL state (filters, tabs, pagination) into local state — read it from the router/`searchParams`. Never mirror form state into a parallel `useState` — let the form library own it.
  - Derive, don't duplicate. Computed values (totals, filtered lists, "is form valid") must be derived inline or via `useMemo` from their source — never stored as a separate state variable that has to be kept in sync.
  - Don't invent a second store for data already living in the API cache, the URL, the form, or a parent's props. If two places hold "the same" value, one of them is a bug waiting to drift.
  - When you must temporarily lift state (e.g. optimistic UI), the canonical source still wins on reconciliation — wire it through React Query's `onMutate`/`setQueryData`/invalidation rather than maintaining a parallel client copy.
